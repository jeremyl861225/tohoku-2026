# 決策紀錄

為什麼這樣排。改行程前先讀這份——多數安排都是有原因的。

---

## 為什麼是南東北，不是原本的東北大環線

初版排的是仙台→松島→平泉→乳頭溫泉→十和田湖→奧入瀨→弘前→五能線→秋田→仙台，
**1,129 km／18:39**（Google 實測）。那個版本有三個問題：

1. **9/23 的乳頭溫泉、9/24 的十和田飯店、9/25 的弘前、9/26 的秋田——四晚全部訂不到。**
   じゃらん 與楽天的空室日曆一致顯示無房，ドーミーイン 兩家連官網也是無。
2. D5 的景點順序在折返（十二湖排在不老ふ死之前），多花 26 分／22 km，
   而且最後 2 小時全在天黑後開 R101 海岸線。
3. D2 的辰子像排在日落之後（17:45 到，日落 17:36），看不到東西，
   還害人 19:01 才到休暇村——而該旅館門限是 18:30。

改成宮城・山形・福島之後：**595 km／11:06，里程少 47%、行車少 40%**，
最長的一天從 4:27 降到 3:14，夜間駕駛完全消失，而且五晚全部訂得到。

## 為什麼是逆時針

仙台空港 → 仙台 → 松島 → 鳴子 → 銀山 → 山寺 → 米澤 → 會津 → 五色沼 → 遠刈田 → 御釜 → 仙台空港。

**關鍵是御釜的位置。** 藏王御釜是折返支線，從哪邊上去都要原路下來。
把它夾在山形段（蔵王温泉 → 御釜 → 米澤）時，實測 **多 61 分／38 km**。
放到最後一天、從宮城側的遠刈田上去，下山方向就是回機場的方向——支線成本降到最低，
整條線也變成不走回頭路的環線。

代價是最後一晚必須住遠刈田／白石。這一晚是週六，本來擔心房量，實查有 115 間，沒問題。

## 訂房日程是倒過來排的

三個硬日子：**9/22（国民の休日）、9/23（秋分の日）、9/26（週六）**。
2026 年的シルバーウィーク（9/19–23）是 11 年來第一次，日本國內旅遊需求會集中在前兩天。

所以：

- 難訂的日子放**房量大的城市**——9/22 仙台（420 間）、9/23 大崎（120 間）、9/26 白石・藏王（115 間）
- 最難訂的**銀山溫泉放在 9/24（週四）**，全週最好訂的一天

這是刻意的順序安排，不要為了「先玩溫泉」把銀山往前挪。

## 鶴ヶ城為什麼在 D5 早上而不是 D4 傍晚

天守 **16:30 停止入場**。D4 從銀山出發、經山寺與米澤，實測 3:14 車程加上停留，
到會津已接近 16:10——當天進不去。所以 D4 傍晚安排七日町散步與晚餐，
鶴ヶ城留到隔天早上，順便接五色沼。

## D3 為什麼只開 49 分鐘

刻意留的喘息日。D2 是連假最後一天、景點密集；D4 是全程最長行車日又要爬 1,015 階。
中間夾一天只開 49 分鐘的日子，是為了讓 D4 有體力。

而且**銀山溫泉的重點在天黑之後**——煤氣燈點亮後的木造街景，白天來看不到。
早到、慢慢泡、等天黑，本來就不該趕。

## 為什麼不用東北高速 Pass（TEP）

初版有考慮，因為舊路線高速里程長。南東北版的高速段短（多數是国道），
逐段付費即可，TEP 的定額划不來。也省掉「取車時必須當場申請、事後不能補辦」這個風險點。

## 地圖為什麼改用 GeoJSON 而不是 basemap

初版的地圖靠 `basemap` + GSHHS 離線海岸線資料。在這台機器的 Python 3.14 上
**basemap／matplotlib／numpy 全部裝不起來**（externally-managed 環境，basemap 也還沒支援 3.14）。

改成從公開的日本行政區 GeoJSON 抽出宮城・山形・福島三縣，
用 Douglas-Peucker 簡化到約 400 m 誤差（18 KB，可進版控），
再用純 Python 做 Mercator 投影輸出 SVG。**現在地圖沒有任何第三方依賴**，
副作用是縣界也一起畫出來了，對這條跨三縣的路線反而更有用。

## 已知取捨

| 取捨 | 理由 |
|---|---|
| 沒排大內宿 | 在南會津，從會津若松來回約 2 小時，塞不進 D5 而不犧牲五色沼 |
| 沒排藏王溫泉（山形側） | 與遠刈田同為藏王山麓，選宮城側是為了讓御釜順路 |
| 沒排最上川舟下り | D3 加它要多約 1 小時車程；列為彈性選項 |
| 白石城可省略 | 使 D6 多 26 分／20 km。御釜若耽誤就直接跳過 |
| 9 月底看不到紅葉 | 鳴子峽的紅葉在 10 月下旬–11 月上旬，此行偏早，看的是綠谷與岩壁 |
| 9 月底吃不到宮城牡蠣 | 產季一般 10 月才開始，松島改以穴子為主 |
